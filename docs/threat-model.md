# PromptGate 威胁模型

> 状态：已确认
>
> 参考：本威胁模型只覆盖 PromptGate 作为软件库的责任边界。它不宣称解决操作系统级隔离、网络层安全或供应链攻击。

---

## 1. 系统边界

```
┌─────────────────────────────────────────────────────┐
│  宿主应用（Agent 框架 / IDE / CI Runner）              │
│                                                       │
│  ┌─────────────┐    ┌──────────────┐                 │
│  │  LLM Agent   │───→│ 工具调用意图  │                 │
│  └─────────────┘    └──────┬───────┘                 │
│                             │                          │
│                             ▼                          │
│                    ┌─────────────────┐                │
│                    │   PromptGate     │ ← 本项目       │
│                    │   (Gate 判定)    │                │
│                    └────────┬────────┘                │
│                             │                          │
│                    ┌────────▼────────┐                │
│                    │  真实工具执行     │ ← 宿主负责     │
│                    │  (FS/Shell/API)  │                │
│                    └─────────────────┘                │
│                                                       │
│  ─ ─ ─ ─ 信任边界 ─ ─ ─ ─                             │
│  外部输入                                            │
└─────────────────────────────────────────────────────┘
```

**PromptGate 负责**：接收 (tool, action, resource) 三元组，返回 Allow/Deny/AskUser。
**PromptGate 不负责**：工具的真实执行、Agent 的行为、操作系统级的隔离。

## 2. 攻击面

### 2.1 需要你分析的攻击方式（至少写 3 种）

**攻击 1：路径遍历绕过**
- 描述：攻击者利用 `..` 路径段跳出策略允许的目录范围，访问受保护的父目录文件
- 举例：策略允许 `read_file("workspace/*.mbt")`，攻击者构造 `resource = "workspace/../../.env"`
- 防御思路：匹配前规范化路径（resolve `..` 和 `.` 为绝对路径），拒绝规范化后仍在允许前缀之外的资源

**攻击 2：通配符误匹配**
- 描述：通配符 `*` 不跨越域名边界，但攻击者注册相似域名使模式误匹配
- 举例：策略 allow `(api_call, *, "api.example.com/*")`，攻击者构造 `resource = "api.example.com.evil.com/api"`
- 防御思路：`*` 只匹配一层路径或标签，不跨越 `.` 边界；提供 `**` 作为显式的跨层通配符

**攻击 3：时序攻击（TOCTOU）**
- 描述：Gate 判定和使用之间的时间窗口内，资源指向的实体被替换（Time-of-Check to Time-of-Use）
- 举例：Gate 判定通过后、工具执行前，资源路径指向的文件被替换为敏感文件
- 防御思路：PromptGate 不解决 TOCTOU（这是宿主的职责）；文档明确声明此边界，建议宿主使用文件描述符而非路径来避免

**攻击 4：规则顺序绕过（策略注入）**
- 描述：如果策略支持动态添加规则，攻击者可能插入 allow 规则在 deny 规则之前，改变判定结果
- 举例：策略已有 `deny: (read_file, *, "*.env")`，攻击者通过 API 注入 `allow: (read_file, *, "*.env")` 并确保其优先级高于 deny
- 防御思路：deny 规则始终优先于 allow 规则（硬编码优先级），不受规则添加顺序影响；动态策略修改需要显式 API 并记录审计

## 3. 明确不防御的威胁

以下威胁不在 PromptGate 的责任范围内，由宿主应用或操作系统负责：

- **恶意 Agent 本身**：PromptGate 不检测 Agent 是否被 prompt injection 操控——它只管每个工具调用是否符合策略
- **操作系统级攻击**：绕过 PromptGate 直接调用 OS API 的行为由宿主环境的 sandbox 负责
- **策略文件篡改**：策略文件的存储和完整性保护由宿主负责（类比 `/etc/sudoers` 的权限保护）
- **侧信道攻击**：通过计时代码路径差异推断策略内容——PromptGate 不做 constant-time 保证
- **内存读取攻击**：PromptGate 不加密内存中的审计日志

---

## 4. 安全假设

PromptGate 的正确运行依赖以下假设：

1. **宿主正确集成**：宿主在每个工具调用前都调用了 `gate.judge(tool, action, resource)`
2. **策略完整性**：策略文件在加载后未被篡改
3. **时间可信**：会话过期时间依赖的系统时钟是准确的
4. **单线程执行**：Gate 判定是原子操作，不存在并发的判定-执行窗口（宿主可加锁保证）
